ReadyUp

Pre-deployment checks, written in TypeScript and run from the command line.

rdy run

ReadyUp is a command-line tool. A project writes its pre-deployment checks in TypeScript, groups them into a kit, and runs them with rdy run before a deploy, on a laptop or in CI. The next five minutes: why it exists, what a check looks like, what a run does when a check fails, and how to start.

Most teams already have deploy checks. They live in a wiki page, in a channel thread, and in whoever deployed last time. The code moves and the list does not. Nobody runs the list the same way twice, and the thing it was meant to catch shows up after the deploy, when it is expensive to fix. That is the gap.

One file of checks, one command

A kit is a file of checklists; rdy run runs them and prints what to fix

The idea is small. A kit is a file. It exports checklists, and a checklist contains checks. One command, rdy run, runs them and prints one line per check: a pass, or a failure with the reason and a fix hint that the kit author wrote. The exit code says whether the run passed, so the same command works in a terminal and in a pipeline.

Writing a check

for kit authors

rdy init
This is the kit that rdy init writes. A check is a few fields. The name states what must be true. The check function returns true, or false with a detail. Severity says what a failure costs: error fails the run, warn is reported and does not. Fix is the hint that prints when the check fails. Everything else is structure: the checklist, and one helper import.

Running it

NODE_ENV unset

The warning is reported; only a failure at or above fail-on fails the run

Compile the kit and run it with NODE_ENV unset, and this is what prints. One line per check. The failed line states its claim, and the reason sits beneath it. The fixes are recapped at the end, then the count line, which leads with the worst severity. The verdict names the threshold: the run passed, because a warning is below fail-on error, so the exit code is zero.

The same run, as rdy prints it

Here is a kit with nesting. package.json exists passes, so the check under it runs. build output present fails, and its severity is error. Its two children never run: they are reported as blocked, because their parent failed. NODE_ENV is set fails too, but at warn. base image is pinned does not apply here, so it is skipped. Each result counts once in the total: one error, one warning, one passed, two blocked, one skipped. Then the verdict. This run fails on error. The error fails it; the warning alone would have left it passing, with exit code zero. Exit code one is what CI acts on. And this is what rdy printed for the same run: the same tree, the fixes, the total, the verdict.

Gating a pipeline, trusting a shared kit

for CI owners

The exit code is the gate

rdy run
  • exit 0Ran and found no problems
  • exit 1Ran and found problems fix the repo
  • exit 2Could not complete the invocation fix the invocation

A kit that another team publishes

publisher

rdy compilebundles the kit

git committhe bundle and its manifest

rdy verify --rebuildin CI: fails on a bundle that no longer reproduces from its source

consumer

rdy run --from npm:@acme/eslint-configthe kit published with the installed version

rdy run --from github:acme/ops@v2the kit committed at that ref

One exit code gates the pipeline; a published kit runs at the version the project has

Two questions for a CI owner. Gating: the exit code is the contract. Zero, no problems. One, fix the repo. Two, fix the invocation. Trust: a team publishes a kit by committing the compiled bundle and its manifest, and runs verify with rebuild in CI, which fails if the bundle no longer reproduces from its source. Consumers run it from the package they already install, or from the repository at a pinned ref.

Get started

Node 24 or later
  1. pnpm add --save-dev readyup esbuild esbuild compiles the kits
  2. rdy init writes .config/readyup.config.ts and the starter kit .readyup/kits/default.ts
  3. rdy compile bundles the kit
  4. rdy run runs it, locally or in CI

npmjs.com/package/readyup rdy help lists the doc topics in the terminal

To start: add readyup and esbuild as dev dependencies, on Node 24 or later. rdy init writes the config and the starter kit from earlier. rdy compile bundles it, and rdy run runs it, the same way locally and in CI. The docs are on npm and in the terminal: rdy help lists the topics. Questions?
