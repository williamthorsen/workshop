ReadyUp

One command reports what is wrong and how to fix it.

ReadyUp is a command-line tool. A project writes down what must be true before work starts, before a deploy, or before a release, and one command, rdy run, checks it. This is a run in which two of those things are not true: each failure, the reason under it, and a fix that the author of the check wrote.

A check is a few lines of TypeScript

A name, a test, and the fix to show when it fails.

{ name: 'Docker daemon is running',
  check: () => dockerInfo().status === 0,
  fix: 'Start Docker, then run the checks again' }

One command runs it anywhere

On a laptop, in CI, or from a kit that a package or a repository publishes.

$ rdy run
$ rdy run --from npm:@acme/ui
$ rdy run --from github:acme/diagnose

Checks group into checklists and kits

A kit is one file, and a check can hold checks of its own.

kit        .readyup/kits/onboarding.ts
checklist  machine · repo
check      ✅ Node version matches .nvmrc
check      ❌ .env sets every required key

The result is an exit code and a JSON report

A pipeline gates on the exit code, and a script or an agent reads the JSON.

$ rdy run --json
{ "passed": false, "counts": { "errors": 1, … },
  "kits": [ { "name": "onboarding", … } ] }
exit 1

ReadyUp is that list. A check is a few lines of TypeScript. One command runs the checks, from a laptop, from CI, or from a kit that a package or a repository publishes. Checks group into checklists and checklists into kits. The output is for a person; the exit code and the JSON are for a pipeline or an agent.

Every tool the project installs can audit it

The tools a project installs can audit it. The config on the left lists the sources: packages that publish a kit alongside their code. rdy run --sources runs the default kit of every one of them. rdy, on one page

rdy help <topic> prints the full docs in the terminal

Kits

rdy init
writes .config/readyup.config.ts and a starter kit, .readyup/kits/default.ts
rdy compile
bundles each kit next to its source and records it in .readyup/manifest.json
rdy verify --rebuild
fails on a bundle that no longer reproduces from its source; for CI
rdy list
lists the kits and checklists that a run would find
rdy run --jit
runs the TypeScript source without compiling; the loop while writing checks

Where the kit comes from

rdy run [kit]
the repository's own kit: default, or the one named
--from npm:@acme/ui
the kit published with the installed version of a package
--from bitbucket:ws/repo@ref
the kit committed in a Bitbucket repository at a ref; main when none is named
--from github:org/repo@ref
the same, from GitHub
--sources
the default kit of every source that the config lists, with a summary table

What a run reports

--fail-on error|warn|recommend
the severity that fails the run; error by default
--report-on error|warn|recommend
the severity from which results are listed; the counts are unchanged
--detail summary
the failures and their fixes alone
--json
the whole run as one JSON document, for a pipeline or an agent
--style rich|plain
the marks, or words that a pipe and a log can read
--quiet
withholds the lines of checks that passed

Exit codes

0
nothing failed at the threshold
1
something did: fix the repo
2
the invocation could not complete: fix the invocation

Everything from today on one page: the commands that make a kit, the places a kit can come from, the flags that shape what a run reports, and the three exit codes that a pipeline reads. The full docs are in the terminal under rdy help.
